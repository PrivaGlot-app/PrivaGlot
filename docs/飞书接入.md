# 飞书接入指南（v4）

学生手机上装一个飞书 App，跟机器人单聊上课：选学生 → 点「上课」→
语音/文字对话（语音 → ASR → 大模型教师 → 语音条回复）→ 下课自动出报告
和 AI 进度评估。**交互与网页版同一套逻辑**：老师只在显式开课后才说话，
学生档案由你显式创建或点选，没有自动建档。

**不需要域名、不需要 HTTPS、不需要 ICP 备案**：机器人通过飞书的
WebSocket 长连接收事件，服务端零公网入站端口，境内/境外 VPS 均可运行。

```
学生（飞书 App 语音条）
   │  飞书服务器 ⇄ 长连接（出站 WebSocket，由官方 SDK 维护）
   ▼
run_feishu.py（app/channels/feishu/）
   │  opus → WAV（ffmpeg）→ ConversationKernel（app/core/kernel.py）
   │  ASR / LLM / TTS（小米 MiMo 云端）
   ▼
回复 = 一条文字气泡 + 一条语音条（整轮合成拼接，>55s 自动分段）
```

## 一、创建飞书应用

### 方式 A（推荐）：部署时手机扫码，自动创建

双击「**飞书部署.bat**」。部署脚本发现还没有飞书凭据时，会自动打开
飞书授权页引导你：

1. 用手机飞书 App 的「扫一扫」扫浏览器页面上的二维码；
2. 在手机上点一次「确认创建」。

完成。应用由飞书自动创建（名称预填「PrivaGlot AI 外教」），机器人能力、
消息收发 / 语音资源等权限、WebSocket 长连接事件订阅
（`im.message.receive_v1` 等）全部按官方智能体应用模板预置好，
App ID / App Secret 由脚本自动写进 `.env`——**全程不需要打开飞书开放
平台，也没有任何复制粘贴**。之后自检、启动都由脚本完成。

**扫码前提（重要）**：你的飞书账号名下要有**自己创建**的企业。
纯个人账号（豆包账号）也能扫，应用会创建成功，但它落在个人租户——
机器人永远无法触达你（消息发不进个人租户）。请先在手机飞书创建
企业（免费，1 分钟）：**左上角头像 → 「登录更多账号」→「创建企业
账号」**，输入手机号码；后面两步（完善基础信息、邀请同事）都能直接
跳过。创建完确认左上角头像已切到新企业，再扫码；**别用公司号**（应用
会建进雇主组织）。部署脚本会自动探测触达链路：命中时现场指引你创建
企业，并自动重新出二维码让你再扫一次（新应用会建进你的企业）。

- 预置权限是官方模板（约 36 项），为本项目所需权限的超集；创建即生效。
- 国际版 Lark 组织同样可用：脚本会自动识别并写好 `FEISHU_DOMAIN`。
- 扫码超时或被拒绝时，脚本会退回方式 B，或直接重跑一次即可。
- 想把权限授予一个已有应用：运行
  `python setup/feishu_qr_register.py --out 凭据.json --app-id cli_xxx`。

### 方式 B（备用）：手动创建（约 10 分钟，人工操作）

适用：扫码流程走不通、或需要模板之外的权限/配置时。

1. 打开 [飞书开放平台](https://open.feishu.cn/)，用手机号注册/登录；
   按提示创建一个**企业自建应用**（组织免费创建，你就是管理员）。
2. 应用详情页「凭证与基础信息」里拿到 **App ID**（`cli_` 开头）和
   **App Secret**，部署脚本提示时粘贴（或手工写进 `.env`）。
3. 左侧「应用能力 → 添加应用能力」，开启**机器人**。
4. 左侧「权限管理」，搜索并开通以下权限：
   - `im:message`（获取与发送单聊、群组消息）
   - `im:message:send_as_bot`（以应用的身份发消息）
   - `im:resource`（读取与上传消息中的资源文件——语音下载/上传靠它）
   - `contact:user.base:readonly`（可选：首次联系自动建档时读取飞书昵称）
5. 左侧「事件与回调」：
   - 订阅方式选择 **「使用长连接接收事件」**（不要选回调地址——这正是
     免域名免备案的关键）；
   - 添加事件：**接收消息 `im.message.receive_v1`**。
6. 「版本管理与发布」创建一个版本并发布。自建应用由你自己的组织管理员
   （就是你）审核，通常几分钟内可用。

## 二、配置服务端

`.env` 里追加（模板见 `.env.example`）：

```ini
FEISHU_APP_ID=cli_xxxxxxxx
FEISHU_APP_SECRET=xxxxxxxx
```

服务端要求与网页版相同：Python 3.11+、ffmpeg 在 PATH、`MIMO_API_KEY`
已配置。依赖装一次：

```bash
.venv/Scripts/pip install -r requirements.txt   # 已含 lark-oapi
```

先自检，再启动：

```bash
python run_feishu.py --selftest   # ffmpeg / SDK / 凭据 / 联网 / opus 转码
python run_feishu.py              # 启动机器人（前台常驻；配合 systemd/NSSM 守护）
```

网页版（`python run.py`）可以继续同时用：两者共享 `data/` 里的学生档案与
教材，但**避免同一学生同时在两边上课**（进度文件会互相覆盖）。

## 三、聊天里能做什么

接入分两种人，别混：

- **部署者（你）**：部署时扫码的人。应用就创建在你自己的组织里，
  你是所有者，扫码完即可直接和机器人单聊——部署流程里看不到
  "加组织"这一步，因为你自己就是组织成员。
- **其他使用者（如孩子的家长用他们自己的手机）**：自建应用只对组织内
  成员可见——他们的飞书账号**必须先被邀请进你的组织**（成员管理 →
  邀请成员，免费版够用），然后才能搜到机器人、发起单聊。

想验证：拿一个没被邀请的飞书账号搜机器人——搜不到；邀请进组织后立刻
能搜到。

### 学生侧（发语音/文字给机器人）

| 指令 | 作用 |
|---|---|
| 学生 / 切换 学生名 | 打开**学生选择卡**：点选任意档案为当前学生（网页端选择器的等价）；「绑定 学生名」同样可用 |
| 新建学生 姓名[,年龄[,语言背景][,兴趣]] | 建档并设为当前学生，如 `新建学生 周一鸣,9,dogs`；语言背景=中文/海外华人家庭（或 `语言:海外华人家庭`）；无参数递**建档表单卡**（姓名必填，含母语下拉） |
| 上课 | 从上次练的单元继续；第一次上课自动进入选教材引导 |
| 选课 | 打开**选课主页**（拓扑 v2 的主页卡，网页端 coursePicker 等价）：按教材分组列出单元与进度，点单元即开课；创建教材/自由对话/选老师/换学生也都住在这张卡上 |
| 上课 序号 / 序号-单元 | 指定教材开课，如 `上课 1`、`上课 1-2` |
| 自由对话 | 切到自由聊天模式（脱离教材） |
| 直接发语音 / 文字 | **课中**=口语输入，老师照常回复（打字练习）；**没有进行中的课时不会召唤老师**——隔夜挂着的课先自动结算，然后递上学生卡或面板 |
| 下课 | 结束本次课：词汇报告 → AI 进度评估 → 保存档案 → 报告卡 |
| 进度 | 查看当前学生的单元进度百分比 |
| 选老师 / 设老师 老师id / 设风格 风格 | 网页端「高级设置」的等价：选老师卡；换老师重置风格为该老师默认；选择被记住，下次开课沿用 |
| 面板 / 主页 | 打开选课主页（没选学生时递学生卡）。课中打「面板/选课」一律回课中控制卡，不下课 |
| 帮助 | 指令一览 |

开课成功后会收到**课中控制卡**（含「⏹ 下课」），课模式下还会收到 **🎯 本课目标卡**（目标词汇开课快照）。

**产品特例（防止后续误判为缺口）**：
1. 网页端「我的教材」的 **AI 提取粘贴工作流**（复制提示词 → 粘贴 AI 回复 → 解析填入）**仅 GUI 有，飞书通道有意不做**。飞书建教材靠分步向导 + 打字/表单卡；这不是待补缺口，是通道形态取舍（2026-09-22 用户裁定）。
2. **课中实时词汇命中反馈**（GUI 目标面板上"说对一个词徽章立刻+1"）**仅 GUI 有，飞书有意不做**：聊天流里逐词发卡会刷屏，编辑已发出的卡又有高风险。飞书只做开课时的目标快照卡 + 下课报告里的命中汇总，信息不丢（2026-09-22 用户裁定）。

首次联系机器人（发文字或语音）会收到**学生选择卡**——和网页端首屏一样
先选学生：点选已有档案，或「➕ 新建学生」走建档表单卡（姓名必填、年龄/
兴趣选填，提交后自动设为当前学生；飞书只记"当前学生"这个指针，档案本身
存在你自己的服务器上，与网页端完全共用）。选好学生后自动落到**选课
主页**：点单元开课，「自由对话」闲聊；没有进行中的课时，语音和文字都
只会得到引导，跟网页端开课前老师保持沉默一个道理。发「上课」（不带
参数）= 从上次练的单元继续；第一次上课只有一本教材时直接开，多本时
打开选课主页挑。

### 管理面（状态 / 换Key / 教材管理，全员开放）

**没有管理员概念**（2026-09-22 用户裁定：应用场景只有学生本人与家庭成员，
无陌生人）。`状态`、`换Key`、`教材管理` 对所有人开放；选课主页上的
「➕ 创建教材」按钮所有人可见。`FEISHU_ADMIN_OPEN_ID` 只剩一个用途：
开机欢迎卡推给扫码部署的人——那是"机器人只能主动找它认识的 open_id"
这一平台约束，不是权限；「绑定管理员」指令已退役。

| 指令 | 作用 |
|---|---|
| 状态 | 一屏体检：Key / ffmpeg / 教材数 / 学生档案数 / 绑定数 |
| 换Key sk-xxxx | 换 MiMo Key：先真实验证再生效（内存 + `.env` 同步），无需重启 |
| 教材管理 | 聊天里建教材/加单元/改单元/改书名/删单元/删教材——分步向导、逐条回显确认、保存前校验 |

**改单元是覆盖式编辑**（2026-09-22 用户裁定）：修改单元的 标题/词汇/句式/语法
时，机器人先回显当前内容，你发送**完整的新内容整段替换**——要保留的原内容
也要包含在内（加一条=多发，删一条=少发）；清空则发「清空」。校验不过会
告诉你原因并让你原地重发，不会前功尽弃。内置示例教材不可修改。

教材管理的设计约束（与产品共识一致）：录入协议是
纯文字指令，**不依赖飞书特有能力**（无云文档、无 LLM 解析原始教材）；校验
复用网页端同一套规则（`course_engine.validate_book_dict`），校验不过不落盘。
词汇请**打字**发送（英文语音识别不可靠），支持逗号/顿号/换行分隔，词组
（如 short hair）不受影响。

### 按钮（卡片）与面板：不用背关键词

机器人会在**合适的时机主动递上带按钮的卡片**，点了就等于发对应指令
（底层翻译成同一条指令通道，文字回复永远照常可用）：

- **学生选择卡**：首次联系机器人随欢迎语收到，发「学生」随时找回——
  网页端学生选择器的等价物：点学生名切换当前学生，「➕ 新建学生」
  递建档表单卡（姓名必填，年龄/语言背景/兴趣选填）。没选学生前，上课/
  进度/语音都会先递这张卡。
- **选课主页（主页卡，拓扑 v2）**：聊天里的主页 = 网页端选课页的等价。
  建档/切换学生成功后**自动跟上**，发「选课」「面板」「主页」随时找回。
  卡上两层内容：单元列表（按教材分组、带进度，点单元开课）+ 功能键
  「➕ 创建教材」「💬 自由对话」「👩‍🏫 选老师」「👤 换学生」——与 GUI
  的层级一致：这些动作在网页端全部住在选课页，不再有一张"什么都能点
  的控制面板"（旧面板卡已于 2026-09-23 退役）。
- **开机欢迎（仅部署者）**：部署者扫码后机器人已知道你是谁——服务启动
  时若你还没有当前学生，会主动推一次欢迎+学生卡（没配 Key 时推 Key
  引导卡）；建过档/选过学生后不再推。其他使用者仍需先给机器人发一条
  消息（平台拿不到他们的 open_id，硬约束）。
- **课中控制卡**：开课成功后自动收到，标题「🎓 上课中」，含「⏹ 下课」
  按钮——不用背「下课」指令（GUI 课中控件的等价）。
- **本课目标卡**：上课模式开课时收到「🎯 本课目标」，是目标词汇的开课
  快照；课中实时命中反馈仅网页有（见上文特例声明）。
- **选老师卡**：发「选老师」收到——网页端「高级设置」的等价：点老师
  切换（换老师后风格重置为该老师默认），再点风格微调；选择被记住。
- **下课报告卡**：每次下课（含自由对话结束）在报告后附「接下来？」卡
  （再来一课/选课/自由对话/查看进度/切换学生）。
- **确认卡**：教材管理里需要「确认/取消」的操作（保存、删除、改单元
  落盘）会附按钮。
- **教材管理菜单卡**：进入教材管理只收到这一张卡——书单在卡内，
  建教材/加单元/改单元/改书名/删单元/删教材/看教材/退出全按钮化，不用
  背指令格式（带序号的指令点了会先告诉你用法，先「看教材」查号）。
  向导进行中再点任何菜单按钮会先自动取消上一步，指令不会被当成内容
  吃掉；保存/落盘后会重新递上这张卡，退出管理则回到面板卡。
- **改单元字段卡**：「改单元 书序号 单元序号」后收到——点 标题/词汇/
  句式/语法 选择要改的一项；随后的新内容是**整段覆盖**（见管理面说明），
  多行内容仍直接打字。
- **向导表单卡**：建教材/加单元的标题类步骤附带输入框的卡片，点「提交」
  等于把内容打字发出去；跳过/完成的步骤附对应按钮。词汇、句式这类
  多行内容仍直接打字（单行输入框装不下）。
- **Key 引导卡**：发「换Key」（不带参数）会收到一张带输入框的卡片——
  Key 在卡片里提交，**不会留在聊天记录里**，提交后先真实验证再生效。
  卡片正文就是「怎么拿到 Key」的完整引导（注册链接、防坑说明、步骤），
  与网页端 setupOverlay 同源：文案由供应商档案（`app/vendors/`）下发，
  改小米活动只改档案，两个形态一起生效。没配 Key 时的冷启动引导
  也递这张卡（网页端 setupOverlay 人人可见的等价）。

卡片按钮的点击回调走长连接的 `card.action.trigger`（官方模板已预置，
无需任何后台配置）。按钮始终是可选加速：所有功能用文字指令都能完成。

### 机器人菜单（可选，不影响任何功能）

飞书开放平台支持给机器人配菜单，但菜单项与 `application.bot.menu_v6`
事件**只能在开放平台后台手动配置**（没有开放 API）。想用的话：
「应用功能 → 机器人 → 菜单配置」里添加菜单项（类型选事件，`event_key`
直接填指令文字，如 `进度`、`教材管理`），并在「事件与回调」里订阅
`application.bot.menu_v6`。通道会把菜单点击翻译成对应文字指令。
**不配置菜单时所有功能照常可用**——文字指令才是唯一契约，这也是将来
接入其它聊天平台时协议不变的关键。

## 四、常见问题

- **扫码创建的应用，机器人没反应**：先跑 `python run_feishu.py --selftest`；
  自检通过但收不到消息时，按方式 B 第 6 步到开放平台确认应用是否需要补一个
  版本发布，以及事件订阅里是否有 `im.message.receive_v1`（扫码模板正常会带）。
- **发语音没反应**：先跑 `python run_feishu.py --selftest`；确认长连接订阅方式选对了、`im.message.receive_v1` 事件已添加、应用版本已
  发布。服务重启后飞书会自动重连，不需要重开应用版本。
- **语音条发不出来**：确认开通了 `im:resource` 和 `im:message:send_as_bot`。
- **家长搜不到机器人**：自建应用只对组织内成员可见。扫码部署的人
  （组织所有者）天然可用；**其他使用者必须先被邀请进组织**（成员管理 →
  邀请成员），然后重新搜索即可。详见第三节开头的说明。
- **海外用 Lark**：`.env` 里把 `FEISHU_DOMAIN=https://open.larksuite.com`。
- **改了学生名字/教材**：网页端改动即时生效；手工改文件后重启
  `run_feishu.py`（课程目录启动时扫描一次）。
- **飞书端建的/改的教材，网页端看不到**：教材目录是每个进程的内存缓存，
  飞书进程落盘后网页进程要**重启**才可见（反之亦然）。**这是已知行为，
  不是缺口**（2026-09-22 用户裁定：当前"本机网页+飞书"双进程并行只是
  测试期临时形态；未来部署为「飞书+公网VPS」「本机部署」两种形态，
  各自单进程运行，不存在此问题）。测试期确需两边同步时重启另一边即可。

## 五、隐私提示（请如实告知家长）

课程数据（档案/会话记录/教材）仍然只存在你自己的服务器上；但走飞书通道
意味着**孩子的语音和对话文字会额外经过飞书（字节跳动）的服务器**，同时
语音识别与大模型回复仍由小米 MiMo 云端完成。这与本项目的隐私定位是一处
明确的取舍——若家长不接受，请使用网页版（浏览器直连你的服务器）。服务端
不落盘任何学生语音原文：语音即用即弃，档案里只保留 ASR 出的文字。

## 六、给开发者的测试地图

本仓库**不携带任何自动化测试**——契约测试、dry-run 脚本与真机 e2e 脚本都只保留在
维护者本机，普通使用者不需要它们。维护者本机的分布：

| 测试（仅本机） | 内容 | 网络 |

| `tests/e2e_feishu_real.py` | 飞书通道真机全链路 | MiMo |

新增通道（如 Telegram）时：实现 `app/channels/<name>/`，把通道一致性用例换成
新通道的事件形状跑通即可，**不要改 `app/core/`**（内核不变性军规）。
